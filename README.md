MLOps-пайплайн для сервиса-агрегатора такси

Итоговый проект модуля 7 курса MLOps Яндекс Практикума.

Цель проекта

Разработать воспроизводимый ML-пайплайн для обработки данных о поездках такси, обучения нескольких моделей, оценки качества и сохранения лучшей модели.

Используемые технологии

Apache Airflow - оркестрация обработки данных по расписанию.

Pandera - валидация данных.

Yandex Object Storage (S3) - хранение датасетов и моделей.

ClearML - управление ML-экспериментами и пайплайнами.

ClearML Agents - выполнение задач обучения.

Kubernetes (K3s) и Helm - управление агентами.

Docker Compose - развёртывание инфраструктуры.

Python, pandas, scikit-learn, boto3, joblib - обработка данных и машинное обучение.

Обработка данных в Airflow

DAG final_task_dag запускается каждый час.

Основные этапы:

Загрузка исходного датасета из объектного хранилища.

Очистка и преобразование данных.

Проверка структуры данных с помощью Pandera.

Сохранение обработанного датасета в объектное хранилище.

ML-пайплайн в ClearML

Пайплайн состоит из пяти этапов:

load_data - загрузка обработанных данных.

train_model_1 - обучение первой модели.

train_model_2 - обучение второй модели.

evaluate - сравнение моделей по RMSE.

save_model - сохранение лучшей модели.

Используется алгоритм GradientBoostingRegressor с двумя наборами гиперпараметров.

Параметр

Модель 1

Модель 2

n_estimators

100

200

learning_rate

0.05

0.1

Обучение выполняется через два ClearML Agent, развёрнутых в Kubernetes.

Хранение артефактов

Для хранения используется S3-совместимое объектное хранилище.

Логическая структура:

raw/
    uber.csv
processed/
    uber_processed.csv
models/
    best_taxi_model.joblib

Адреса хранилища, идентификаторы ресурсов и учётные данные не публикуются в репозитории.

Запуск

Установка зависимостей:

pip install -r requirements.txt

Запуск ML-пайплайна:

python pipeline.py

Перед запуском необходимо настроить доступ к ClearML и объектному хранилищу.
